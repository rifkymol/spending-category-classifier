# Privacy

A bank statement shows where you live, eat, shop and who you pay. This app is built so that it never has to leave your machine, and so that each promise below is backed by code and, where possible, an automated test.

## Guarantees

| Guarantee | Enforced by | Verified by |
|---|---|---|
| **Uploads are never written to disk.** | `POST /api/classify` reads the file as the raw request body into memory (`read_body` in [`backend/app/main.py`](backend/app/main.py)), with a 5 MB cap. There is no multipart form, because Starlette spools multipart uploads over 1 MB to a temp file. PDFs are parsed from bytes by `pdfplumber`. | `test_upload_writes_no_files` ([`test_api.py`](backend/tests/test_api.py)) posts a >1 MB CSV and checks that no file appears in the project or in an isolated temp dir (the `isolated_tmp` fixture in [`conftest.py`](backend/tests/conftest.py) points `TMP`, `TEMP`, `TMPDIR` and `tempfile.tempdir` at an empty folder). `test_pdf_upload_writes_no_files` ([`test_bca_pdf.py`](backend/tests/test_bca_pdf.py)) does the same for a normal and a password-protected PDF. |
| **No database, nothing stored between requests.** | The API keeps only the model in memory. Rows exist for one request; edits live in the browser's React state and vanish on reload or "Start over" (unless you turn on "Remember my corrections", see below). | Code review of [`backend/app/main.py`](backend/app/main.py): no storage layer. The no-files tests above. |
| **No financial data in browser storage; only UI preferences `lang`, `theme` and `rememberLabels`.** | The browser's `localStorage` keeps the language (`lang`: `en` or `id`), theme (`theme`: `system`, `light` or `dark`) and the "Remember my corrections" switch (`rememberLabels`: `on` or `off`, off by default) so they survive a reload. All access sits in [`frontend/src/lib/prefs.ts`](frontend/src/lib/prefs.ts), inside `try`/`catch`. Statement rows, amounts and the income you type into the 50/30/20 card live only in React state. | [`frontend/scripts/check-storage.mjs`](frontend/scripts/check-storage.mjs), run in CI: it fails if any file in `frontend/src` uses `localStorage` outside `prefs.ts`, a key other than these three (or a computed key), or uses `sessionStorage`, cookies or the Cache API. |
| **Your corrections are remembered only if you turn it on, only in your browser, and the server never keeps them.** | Opt-in ("Remember my corrections on this device", off by default). [`frontend/src/lib/labelsStore.ts`](frontend/src/lib/labelsStore.ts) is the only code that touches IndexedDB: one database, `scc-labels`, holding per correction only the description, category, direction (DB/CR) and a timestamp (plus a `hint` flag on imported old-format rows, which never trains a model and keeps the row flagged for review); no amounts, dates, income or files. **Forget my corrections** deletes the database (after a confirmation); clearing the site data in the browser does too. When on, the corrections are sent with each upload (JSON body, read in memory with a 12 MB cap, at most 20,000 labels, validated); the server trains a model for that request only ([`backend/classifier/personalize.py`](backend/classifier/personalize.py)) and drops it with the response. Nothing is written, cached or logged (the log line holds only the label count). | `check-storage.mjs` (IndexedDB only in `labelsStore.ts` and only `scc-labels`). In [`test_personalize.py`](backend/tests/test_personalize.py): `test_json_upload_with_labels_writes_no_files` (no file in the project or an isolated temp dir), `test_logs_hold_no_label_text` (`caplog` at `DEBUG`), `test_invalid_label_is_422_without_echo`, `test_request_model_is_not_cached` (two requests with different labels give different results). |
| **Reports are built in memory.** | [`backend/app/reports.py`](backend/app/reports.py) writes CSV, XLSX and PDF into in-memory buffers and streams them back. | `test_reports_write_no_files` ([`test_reports.py`](backend/tests/test_reports.py)). |
| **Logs hold no descriptions or amounts.** | The access log line is method, path, status, duration and row count only; error logs record only the exception type. The `pdfminer` and `pdfplumber` loggers are capped at `WARNING` in [`bca_pdf.py`](backend/classifier/importers/bca_pdf.py), because pdfminer logs raw page text at `DEBUG`. | `caplog` tests at `DEBUG` level that look for known descriptions and amounts in every log message: `test_logs_hold_no_descriptions_or_amounts` ([`test_api.py`](backend/tests/test_api.py)), `test_report_logs_hold_no_descriptions_or_amounts` ([`test_reports.py`](backend/tests/test_reports.py)) and `test_pdf_logs_hold_no_descriptions_or_amounts` ([`test_bca_pdf.py`](backend/tests/test_bca_pdf.py)), which catches the pdfminer leak if the cap is removed. |
| **Errors don't echo your data.** | Import errors never quote row text; validation errors return field locations and messages only. | `test_errors_do_not_quote_rows` ([`test_bca_pdf.py`](backend/tests/test_bca_pdf.py)), `test_bad_category_is_422_without_echoing_row_data` and `test_malformed_json_is_422_without_echo` ([`test_reports.py`](backend/tests/test_reports.py)). |
| **Only your own computer can reach the app.** | [`docker-compose.yml`](docker-compose.yml) publishes ports as `127.0.0.1:8000` and `127.0.0.1:3000`. Dev servers bind to `127.0.0.1` (uvicorn `--host 127.0.0.1`, `next dev -H 127.0.0.1`). CORS allows only `localhost:3000` and `127.0.0.1:3000`. | `docker compose config` shows `host_ip: 127.0.0.1`; `docker compose ps` lists `127.0.0.1:3000->3000/tcp` and `127.0.0.1:8000->8000/tcp`. |
| **Containers can't keep anything.** | Both services run `read_only: true`, as non-root users, with `cap_drop: [ALL]` and `no-new-privileges`. The only writable paths are `tmpfs` mounts (`/tmp`, and Next.js's cache folder), which live in RAM. No data volumes. | `docker compose config`. |
| **No outbound calls, analytics or telemetry.** | `NEXT_TELEMETRY_DISABLED=1` in every npm script (via `cross-env`) and in [`frontend/Dockerfile`](frontend/Dockerfile). No external fonts, CDNs or trackers; the PDF report uses built-in Helvetica. `frontend/src` has no external URL and no remote font fetch; the only font is the bundled Inter (OFL) in `frontend/src/app/fonts/`, loaded with `next/font/local`, never `next/font/google`. The browser talks only to the API you run. | A grep of `frontend/src` finds no `next/font/google` import and no external URL (other than the links in the Inter license text). In the browser's Network tab, every request goes to `127.0.0.1:3000` or `127.0.0.1:8000`. Network access happens only while *building* images (base images and packages). |
| **Reports can't run formulas.** | `safe_text` in [`backend/app/reports.py`](backend/app/reports.py) prefixes `'` to any text starting with `=`, `+`, `-`, `@`, a tab or a carriage return. | `test_safe_text_prefixes_formula_starts`, `test_csv_is_default_and_neutralizes_injection` ([`test_reports.py`](backend/tests/test_reports.py)). |
| **The shipped model knows no real person's spending.** | By default the API trains at startup on [`data/sample_transactions.csv`](data/sample_transactions.csv), 40 made-up rows. Personal models load only through `MODEL_PATH`, which you set. | `test_health` reports `model: synthetic` by default. |
| **Your statements, labels and models stay out of Git and images.** | [`.gitignore`](.gitignore) excludes `data/raw/`, `data/labels/`, `models/`, `*.joblib` and `*.pkl`. [`.dockerignore`](.dockerignore) excludes `data/` (except the sample), `models/`, `*.joblib` and `.git`. | `git status` / `git ls-files`; the leak check described below. |
| **Labels are created by you, not the server.** | "Export labels" builds the CSV in the browser and your browser saves it. Training runs only from the CLI on your machine, and drops unreviewed `model` guesses. | `test_train_multiple_files_drops_model_rows` ([`test_pipeline.py`](backend/tests/test_pipeline.py)). |

## How this was built with a real statement without exposing it

The BCA importer had to work on a real e-statement, but the statement was never pasted into a chat, committed, or sent to a cloud service, including the AI coding assistants used during development.

1. **Masked layout scan.** A local script read the real PDF and printed only its *shape*: every letter replaced with `A` and every digit with `#`, except an allowlist of known column headers and markers (such as `TANGGAL`, `KETERANGAN`, `MUTASI`, `SALDO`, `DB`, `CR`). That showed the column layout, the number format and how descriptions wrap across lines, without revealing any name, merchant or amount.
2. **Synthetic fixture first.** [`backend/tests/bca_fixture.py`](backend/tests/bca_fixture.py) uses `reportlab` to generate a fake statement with the same layout (a placeholder holder name, an all-zero account number and made-up `CONTOH` merchants), including page breaks, multi-line descriptions, a summary block and a password-protected variant. The importer was written and tested against that.
3. **Leak check.** Before committing, the repo was scanned for tokens taken from the real statement (names, account digits, merchant strings). None were found in the repo or in the server log.
4. **Masked real-file checks.** The importer was then run on the real file locally, printing only counts and sums: row counts by direction and DB/CR totals matched the statement's own summary exactly, with no empty descriptions.

Model results in the [README](README.md#results) are reported the same way: aggregate numbers only.

## What this does NOT protect against

- **A compromised machine.** If malware or another user has access to your computer, they can read your statement files, your browser's memory or the running containers. The app can't defend against its own host.
- **Files you keep yourself.** The statement you downloaded, the labels CSV and any saved report are ordinary files on your disk. Protect, back up and delete them like any other financial document.
- **Changing the defaults.** Binding to `0.0.0.0`, publishing ports on your LAN, adding a reverse proxy or mounting volumes removes the protections above.
- **Hosting it for others.** This is designed as a self-hosted, single-user tool. If you run it publicly and other people upload their statements, you become responsible for their personal data, for example as a data controller or processor under Indonesia's Personal Data Protection Law (UU PDP, UU No. 27/2022). That needs authentication, TLS, a privacy notice and much more than this project provides.
- **Supply-chain risk at build time.** Base images are digest-pinned and Python and npm packages are pinned exactly, which limits but doesn't remove the risk of a compromised upstream package.
- **Future optional email.** If an email report is added (see the Roadmap), it will be off by default, but once you turn it on with your SMTP settings, the report leaves your machine.

Found a privacy problem? Please open an issue without attaching any real statement data.
